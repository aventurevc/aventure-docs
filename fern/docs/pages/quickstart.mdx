The first three requests are anonymous — no signup, no credential. The fourth
proves a credential works once you have one.

Prefer a terminal or an AI client? The [CLI quickstart](/cli) and
[MCP quickstart](/mcp) cover the same data through those surfaces.

## 1. List entities

`GET /v1/entities` returns a page of organizations, products, and services.
Add `typeRecord=Company` when you want companies only.

```bash
curl "https://api.aventure.vc/v1/entities?size=5"
```

The response is a page object — the records are in `content`, and the rest
describes your position in the result set:

```json
{
  "content": [ ... ],
  "number": 0,
  "size": 5,
  "totalElements": 12345,
  "totalPages": 2469,
  "first": true,
  "last": false
}
```

`number` is zero-based, so the first page is `0`.

## 2. Narrow it with filters

Filters are query parameters, and most accept the parameter more than once to
mean "any of these":

```bash
curl "https://api.aventure.vc/v1/entities?stage=seed&headquartersCountry=US&size=5"
```

`GET /v1/entities` accepts more than sixty filters covering industry, location,
accelerator cohort, fundraising activity, and operating status.
[Pagination and filtering](/pagination-and-filtering) covers how they combine.

## 3. Find one company by name

Slugs carry the headquarters location, so resolve a name instead of guessing
one. `GET /v1/entities/lookup` is anonymous and returns the full record,
including its `core.slug` and the `core.id` UUID that funding-round, investor, and
people routes take:

```bash
curl "https://api.aventure.vc/v1/entities/lookup?name=Ramp"
```

`urlDomain=google.com` resolves by website instead. A domain is often shared by a
company and the product records under it, and then the answer is a
[`409`](/errors) whose `details.candidate` lists the candidates. Names can also
match more than one record. If candidates are returned, choose one and read its exact slug. Otherwise,
list matches with `GET /v1/entities?entityName=Mercury` and select the intended
`content[].core.slug`. Add `typeRecord=Company` when you want companies only.

## 4. Authenticate

Create a personal API key: sign in at [aventure.vc](https://aventure.vc), choose your account menu →
**Manage account → API keys**, and choose **Add new key**. Load it from your secret
manager as `AUTH_TOKEN` rather than pasting it into a shell history.

`GET /v1/auth/me/permissions` is the cheapest way to confirm the credential is
being read and to see what it reaches:

```bash
curl -H "Authorization: Bearer $AUTH_TOKEN" \
  "https://api.aventure.vc/v1/auth/me/permissions"
```

A `401` means the credential was missing or unrecognized; a `403` means it was
valid but not permitted there. Both arrive as a
[problem detail](/errors) whose `detail` field names the reason.
[Authentication](/authentication) covers service integrations and subscription requirements.

## 5. Search across everything

When you have a phrase rather than a set of filters, `POST /v1/search/all` runs
the entity, person, and news engines and returns a typed result page for each
scope:

```bash
curl -X POST \
  -H "Authorization: Bearer $AUTH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "climate tech seed round"}' \
  "https://api.aventure.vc/v1/search/all?size=10"
```

<Note>
As a signed-in user, this endpoint requires a Pro subscription or trial whose
current period has not ended — check
[Settings → Subscription](https://aventure.vc/settings/subscription). A service
integration holding a client secret reaches it without one.
</Note>

`page` and `size` apply to every scope. Cross-domain `sort` is not supported —
each scope orders its own results by relevance.
