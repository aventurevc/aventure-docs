This page is for developers calling the aVenture API over HTTPS. The first three
requests are anonymous and need no account. The last two need a
[personal API key](/authentication#get-a-personal-api-key).

If you work in a terminal or an AI client instead, the [CLI quickstart](/cli)
and [MCP quickstart](/mcp) cover the same data through those tools.

## 1. List companies

`GET /v1/entities` returns a page of list records. Each record carries its
identity in `core`, supplemental data such as addresses, tags, and funding in
`enrichment`, its funding rounds in `fundraiseRound`, and a research summary in
`research`. `typeRecord=Company` keeps companies and
excludes products, services, funds, and other record types.

```bash
curl "https://api.aventure.vc/v1/entities?typeRecord=Company&size=5"
```

The response is a page object. The records are in `content`, and the other
fields describe your position in the result set:

```json
{
  "content": [ ... ],
  "number": 0,
  "size": 5,
  "totalElements": 12345,
  "totalPages": 2469,
  "first": true,
  "last": false
}
```

`number` is zero-based, so the first page is `0`. Each record's identity is in
`content[].core`, including its `slug` and its `id`.

## 2. Narrow the list with filters

Filters are query parameters. Repeating a parameter means "any of these", and
different parameters must all match:

```bash
curl "https://api.aventure.vc/v1/entities?typeRecord=Company&stage=Seed&headquartersCountry=US&size=5"
```

The endpoint accepts more than sixty filters for industry, location,
accelerator cohort, funding activity, and operating status.
[Pagination and filtering](/pagination-and-filtering) explains how they combine.

## 3. Find one company by name

A slug includes the headquarters location, such as `ramp-new-york-city-ny-us`,
so resolve a name instead of guessing its slug. `GET /v1/entities/lookup-exact` is
anonymous and returns the full record, including `core.slug` and the `core.id`
UUID that funding, investor, and people routes take:

```bash
curl "https://api.aventure.vc/v1/entities/lookup-exact?name=Ramp"
```

`urlDomain=stripe.com` resolves by website instead. When a name or domain
matches more than one record, the API answers [`409`](/errors). If the problem
detail includes `details.candidate`, choose one candidate and read it by its
`id` with `GET /v1/entities/{entityId}`. Otherwise, list the matches with
`GET /v1/entities?entityName=Mercury` and pick the intended record.
When you only have a name and clues such as a location or a source article,
[identify the company](/lookup) instead.

## 4. Authenticate

Create a personal API key at [your API key settings](https://aventure.vc/settings/api-keys)
and load it from your secret manager as `AUTH_TOKEN`, so the key never lands in
your shell history. `GET /v1/auth/me/permissions` confirms the API accepts the
key and lists what it can reach:

```bash
curl -H "Authorization: Bearer $AUTH_TOKEN" \
  "https://api.aventure.vc/v1/auth/me/permissions"
```

A `401` means the credential was missing or unrecognized. A `403` means it was
valid but lacks permission for that operation. Both arrive as a
[problem detail](/errors) whose `detail` field names the reason.

Calls made with your key draw on your plan's monthly allowances.
[Plans and usage](/authentication#plans-and-usage) explains what counts and
where to check it.

## 5. Search in plain English

When you have a phrase instead of a set of filters, `POST /v1/search` plans the
query and searches companies, people, and news together:

```bash
curl -X POST \
  -H "Authorization: Bearer $AUTH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "fintech companies in Austin"}' \
  "https://api.aventure.vc/v1/search?size=10"
```

<Note>
Plain-English search requires a plan that includes it. Without one, the API
answers `402` with `code` `subscription_required`. The
[pricing page](https://aventure.vc/pricing) lists which plans include search.
</Note>

`page` and `size` apply to each record type in the response. Search does not
accept `sort`, because each record type is ordered by relevance.
