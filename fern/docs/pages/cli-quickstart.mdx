This page is for people who want aVenture data in a terminal or a shell script.
The `aventure` CLI calls the same [API](/api-reference) with the same
[credentials](/authentication). Public reads need no credential, so you can run
a real query before you sign in.

<Note>
The CLI requires Node.js 24.18 or later in the 24.x series. The package declares
`node >=24.18.0 <25`.
</Note>

<Steps>
<Step title="Install">

```bash
npm install --global @aventurevc/aventure-cli --@aventurevc:registry=https://registry.npmjs.org/
```

The command is `aventure`. `aventure --version` prints the installed version.

</Step>
<Step title="Run a public read">

This command needs no credential:

```bash
aventure entities summary list --type-record Company --size 3
```

In a terminal, the result is a table with each company's name, `slug`, and
`id`. Add `--json` for the full response envelope.
[Output and exit codes](#output-and-exit-codes) describes each output mode.

</Step>
<Step title="Sign in">

```bash
aventure auth login
```

The command uses the OAuth device authorization grant. It prints a one-time code
and a sign-in URL, opens a browser when one is available, and waits until you
approve the request in the browser. The same command works on a laptop, over
SSH, and inside a container. `--no-browser` prints the URL without opening it.

The CLI stores the credential in your operating-system keyring. When no keyring
is available, it writes `~/.config/aventure/credentials.json` with file mode
`0600`. Access tokens renew automatically from the stored refresh token.

To use a personal API key instead, run `aventure auth login --key`, which
creates and stores a key through the same browser approval. For CI and other
non-interactive environments, set an existing key in the `AUTH_TOKEN`
environment variable.

Commands you run while signed in draw on your plan's monthly allowances.
[Plans and usage](/authentication#plans-and-usage) explains what counts, and
`aventure billing subscription get` prints your current usage.

</Step>
<Step title="Verify">

```bash
aventure auth doctor
```

`doctor` runs every environment check in one call and reports
`{ ok, check: [...] }`. The checks cover the CLI version, the installed schema
package, the API host, the local credential, and whether the command catalog
matches the operations the API serves. It exits `0` when no check failed; a
skipped check does not fail the run. Each failing check names the command that
fixes it.

`aventure auth status` reports where the credential came from, when it expires,
and which API build answered. It never prints the secret itself.

</Step>
</Steps>

## The command shape

`entities`, `people`, and `news` are the three record types. Commands follow the
pattern `aventure <record type> <action>`:

```bash
aventure entities summary list --stage Seed --headquarters-city Austin --size 3
aventure entities lookup get --name Ramp
aventure entities get --entity-id 07895463-8867-4566-9dc8-a30794076bb6
aventure entities fundraise-rounds list --entity-id 07895463-8867-4566-9dc8-a30794076bb6
```

| Command | What it does | Credential |
|------|--------------|------------|
| `entities summary list` | List companies, products, and services, with filters | None |
| `entities lookup get` | Read one full record by name, slug, URL, or domain | None |
| `entities get` | Read one full record by its `id` | None |
| `entities fundraise-rounds list` | List one company's funding rounds | None |
| `entities search` | Filter companies with a JSON body or flags | Signed in |
| `entities lookup` | Decide which company a name refers to, or confirm it is new | Signed in |

`people` has the same `get`, `lookup`, and `search` commands, and `news` has
`get`, `lookup`, and `list`. Run `aventure <record type> --help` for the full list.

### Start from a name

A slug includes the headquarters location, so you cannot guess it:
`--entity-slug ramp` returns `404`. Resolve the name first. The answer carries
the `core.slug` and the `core.id` UUID that other commands take:

```bash
aventure entities lookup get --name Ramp
```

`--url-domain stripe.com` resolves by website instead. When a name or domain
matches more than one record, the answer is [`409`](/errors). If the error
lists candidates, choose one and read it with `aventure entities get --entity-id`.
Otherwise, list the matches and pick the intended record:

```bash
aventure entities summary list --entity-name Mercury
```

Records attached to a company, such as funding rounds, investors, and people,
sit under the company's UUID, so those commands take `--entity-id`, not a slug.

To read many records in one request, sign in and pass several `--entity-id`,
`--slug`, or `--url` values to `aventure entities lookup batch`.

### Search across record types

`aventure search --query "fintech companies in Austin"` searches companies,
people, and news together from a plain-English phrase. `aventure lookup --name`
finds a company or person from a name, with optional `--url`, `--location`, and
`--context` evidence.

<Note>
`aventure search` and `aventure lookup` require you to be signed in.
Plain-English search also requires a plan that includes it; without one, the
command fails with [`402`](/errors). The [pricing page](https://aventure.vc/pricing)
lists which plans include search.
</Note>

## Output and exit codes

Each command accepts an output mode:

- `--text` is the default in a terminal: a table for a list and labeled fields for one record.
- `--data` prints the response data as JSON on success, and an envelope on failure or when the output is too large. It is the default when output is piped.
- `--json` prints the full envelope, capped at 50 KB.
- `--data-full` prints uncapped JSON for programs that bound their own input.
- `--all-fields` adds the detail fields that `--text` hides.

Use `--json` in scripts that need a stable shape. Check `ok` before reading
`data.response`, which holds the API response body.

When the envelope reports truncation, request a smaller page or the specific
funding, people, or news command instead of treating omitted fields as missing
data.

Exit code `0` means `ok` is `true`, and `1` means the call failed, so a script can
branch on the exit code without parsing output.

## Find the command for an operation

`aventure help` accepts an [API reference](/api-reference) `operationId`, a
command path, or a method and path. It prints what the operation needs without
calling the API:

```bash
aventure help getEntity
```

```text
cli: aventure entities get
GET /v1/entities/{entityId}
operationId: getEntity
resource: entities
intent: read
scope: read
mutates: false
destructive: false
mcpTool: aventure_read
body: none
required path flags: --entity-id
required query flags: none
```

`mcpTool` names the [MCP](/mcp) tool that runs the same operation. `scope`
classifies the operation as a read or a write; it does not say whether an
anonymous call is allowed. The operation's `security` declaration in the API
reference decides that. `aventure <command> --help` lists the command's flags,
grouped by whether they go in the path, the query string, or the request body.
