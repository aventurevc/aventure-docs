This page is for anyone who has finished a quickstart and wants a complete
answer instead of a single call. Each step shows the same operation on all three
surfaces.

The question is: **which seed-stage companies in Austin are in the dataset, and
what has one of them raised?** The API and CLI calls below need no credential
or account. For MCP, first connect and sign in with the
[MCP quickstart](/mcp).

<Steps>
<Step title="Narrow the dataset to the companies you mean">

Filters are query parameters on the company list, and they combine.
`typeRecord=Company` excludes products, services, and other record types.
`stage` and `headquartersCity` narrow the companies further.

<Tabs>
<Tab title="API">

```bash
curl "https://api.aventure.vc/v1/entities?typeRecord=Company&headquartersCity=Austin&stage=Seed&size=5"
```

</Tab>
<Tab title="CLI">

```bash
aventure entities list --type-record Company --headquarters-city Austin --stage Seed --size 5
```

</Tab>
<Tab title="MCP">

Call `aventure_read` and name the operation:

```json
{
  "operationId": "listEntities",
  "query": { "typeRecord": ["Company"], "headquartersCity": ["Austin"], "stage": ["Seed"], "size": 5 }
}
```

</Tab>
</Tabs>

`totalElements` counts the whole matching set, not only your page, so it
answers "how many are there". `content` holds up to five records. Each record's
`core.slug` identifies it for the next step.

<Note>
Location filters take the full name, not the postal abbreviation:
`headquartersState=Texas` matches, and `headquartersState=TX` returns no records.
[Pagination and filtering](/pagination-and-filtering) explains how filters
combine.
</Note>

</Step>
<Step title="Open one record">

Take `core.slug` from a record in the previous response, such as
`closing-theory-austin-tx-us`, and read the full record. The response includes
the record's identity, research, linked news, and linked people. Its `core.id`
is the UUID that funding-round operations take.

<Tabs>
<Tab title="API">

```bash
curl "https://api.aventure.vc/v1/entities/lookup-exact?slug=closing-theory-austin-tx-us"
```

</Tab>
<Tab title="CLI">

```bash
aventure entities lookup-exact get --entity-slug closing-theory-austin-tx-us
```

</Tab>
<Tab title="MCP">

Call `aventure_read`:

```json
{
  "operationId": "getEntityLookup",
  "query": { "slug": "closing-theory-austin-tx-us" }
}
```

</Tab>
</Tabs>

<Note>
The API parameter is `slug` on every surface. The CLI names the flag
`--entity-slug` so that it cannot be confused with the `--slug` flag of batch
commands.
</Note>

</Step>
<Step title="Read the funding rounds">

`core.id` from step 2 is the `entityId` path parameter here.

<Tabs>
<Tab title="API">

```bash
curl "https://api.aventure.vc/v1/entities/03418f84-8e9f-4f68-b82c-1fd35a15e083/fundraise-rounds?size=3"
```

</Tab>
<Tab title="CLI">

```bash
aventure entities fundraise-rounds list --entity-id 03418f84-8e9f-4f68-b82c-1fd35a15e083 --size 3
```

</Tab>
<Tab title="MCP">

Call `aventure_read`:

```json
{
  "operationId": "listEntityFundraiseRounds",
  "pathParams": { "entityId": "03418f84-8e9f-4f68-b82c-1fd35a15e083" },
  "query": { "size": 3 }
}
```

</Tab>
</Tabs>

Each round carries `round`, `amountRaised`, `currency`, `dateAnnounced`, and
`investorCount`:

```json
{
  "content": [
    {
      "id": "65296e8c-3445-4db2-b69f-929e7ea1484d",
      "round": "Seed",
      "amountRaised": 2300000,
      "currency": "USD",
      "dateAnnounced": "2023-07-24T00:00:00.000Z",
      "investorCount": 3
    }
  ],
  "totalElements": 1
}
```

`amountRaised` is in the round's own `currency`, and the API does not convert
amounts to USD, so convert before you compare rounds. The amount, currency,
round, and announcement date can each be `null`, and a missing amount does not
mean zero.

</Step>
</Steps>

## The pattern behind other questions

These three steps are the pattern for most questions: **filter a list, open one
record, and read what is attached to it.** People and news work the same way.
Operations for records attached to a company, such as news, people, and
investors, all take the same `core.id`.

When you have a phrase instead of a set of filters, replace step 1 with search:
`POST /v1/search` searches companies, people, and news together, and
`aventure search --query "..."` is the CLI form. Search requires a credential
and a plan that includes plain-English search. The three calls above need
neither.

Calls you make while signed in draw on your plan's monthly allowances; opening a
full record counts one profile view.
[Plans and usage](/authentication#plans-and-usage) explains what counts.

To find the CLI command and MCP tool for any [API reference](/api-reference)
operation, run `aventure help <operationId>`. It prints the route, the required
flags, and the matching MCP tool without calling the API.
