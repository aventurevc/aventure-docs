The aVenture API, CLI, and MCP server all require an aVenture account. Free and
paid plans both work. [Create an account](https://aventure.vc/sign-up), then
choose how you sign in:

| Where you work | How you sign in |
|---|---|
| API | Send an API key as a bearer token |
| CLI | Run `aventure auth login`, or set `AUTH_TOKEN` to an API key |
| MCP client | Sign in through the browser when your client connects |

## Create an API key

1. Sign in to aVenture.
2. Open [API key settings](https://aventure.vc/settings/api-keys).
3. Choose **Add new key**.

Store the key in your secret manager and load it into the `AUTH_TOKEN`
environment variable at runtime. The same page lists and revokes your keys.
Send it on every request:

```bash
curl -H "Authorization: Bearer $AUTH_TOKEN" \
  "https://api.aventure.vc/v1/auth/me/permissions"
```

A `200` confirms the key works and lists what it can reach.

## Sign in from the CLI

```bash
aventure auth login
```

The command prints a one-time code and a sign-in URL, and waits while you
approve in the browser. It works on a laptop, over SSH, and inside a container.
[Developer access settings](https://aventure.vc/settings/developer) lists past
CLI sign-ins and revokes them. In CI, set `AUTH_TOKEN` to an API key instead.

## Connect an MCP client

The [MCP quickstart](/mcp#connect-to-the-hosted-server) lists the hosted URL,
OAuth client ID, and callback settings. Your client signs you in through the
browser when it connects.

## Plans and usage

Your plan decides which features you can use and how much monthly usage it
includes. API, CLI, and MCP calls all draw on the same account.

- **Company and person profile views** count one view per record, per calendar
  month (UTC). Reading the same record again that month is free.
- **Searches and web searches** count one each.
- **Research requests** count against the allowance for adding or updating a
  company or person.
- **Features outside your plan**, such as plain-English search on a plan that
  does not include it, answer `402` with `code` `subscription_required`.

Allowances reset at the start of each calendar month (UTC).

### When you reach a limit

When an allowance runs out, the API answers `429` with `code`
`billing_allowance_exhausted`. The message names the limit you reached and how
to upgrade. Upgrade in any of three places:

- **Website**: [subscription settings](https://aventure.vc/settings/subscription)
  shows your plan, your usage, and every plan you can move to.
- **CLI**: `aventure billing plans list` lists plans with monthly and annual
  prices. `aventure billing plan-changes create --plan <plan>` upgrades a paid
  plan using the card already on file. From the free plan,
  `aventure billing checkout-sessions create --plan <plan>` returns a checkout
  link where you enter a card.
- **MCP**: ask your assistant to list aVenture plans and upgrade you. It uses
  the same plan list and checkout.

If an upgrade needs a payment you have not made yet, the response includes a
payment link to finish it. On plans that offer additional usage, you can turn it
on so requests continue past the allowance up to a spending cap you set.

## Keep credentials safe

Anyone holding an API key or token has the access it grants, and their calls
use your allowances. Keep credentials server-side, load them from a secret
manager, and never ship one in browser code or commit one to a repository.

## When authentication fails

A missing or unrecognized credential returns `401`, and the message says how to
sign in. A valid credential that lacks permission for an operation returns
`403`. Both use the standard [error body](/errors).
