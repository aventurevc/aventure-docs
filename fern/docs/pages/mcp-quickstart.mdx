Choose your app below. You'll sign in to your AI app and to [aVenture](https://aventure.vc/sign-up) separately. You can try the connection with a free aVenture account and no API key. Your AI app may have its own requirements.

## Choose Your AI App

- **Chat apps:** [Claude](#claude), [ChatGPT](#chatgpt), [Grok](#grok), [Perplexity](#perplexity), [Gemini](#gemini)
- **Coding tools:** [Claude Code](#claude-code), [Cursor](#cursor), [Gemini CLI](#gemini-cli)
- **Other:** [Researchly](#researchly), [Another MCP client](#another-mcp-client)

### Claude

Set up the connector on Claude's website or in Claude Desktop. Claude Free allows one custom connector.

On Team or Enterprise, an owner adds the connector under [Organization settings → Connectors](https://claude.ai/admin-settings/connectors). Once it appears under [your connectors](https://claude.ai/customize/connectors/yours), select **Connect** and continue at step 4.

1. Open [Customize → Connectors](https://claude.ai/customize/connectors). Choose **Add → Custom → Web**, or **Add → Add custom connector** if that's what your menu shows.
2. Name the connector **aVenture**, paste `https://mcp.aventure.vc/mcp`, and select **Continue**.
3. Review the detected settings and select **Continue** if Claude shows it again. Set **Authentication** to **Sign in now** and **OAuth client** to **Register automatically**, even if Claude recommends its published identity. aVenture lets Claude register automatically; you don't supply a client ID or secret. Select **Add**.
4. If Claude shows a **Connect** button, select it. When aVenture opens, sign in to your aVenture account and approve the connection. Return to Claude.
5. Open a chat, select **+ → Connectors**, and turn on **aVenture**. Then [try a lookup](#check-the-connection).

If the menu looks different, check [Claude's custom connector instructions](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities) for your version.

### ChatGPT

Use ChatGPT on the web. If **Add custom MCP server** is missing, check your ChatGPT plan and workspace permissions. A free aVenture account doesn't change which features your ChatGPT plan offers.

1. Open [ChatGPT Plugins](https://chatgpt.com/plugins). Choose **+ → Add custom MCP server**.
2. Name it **aVenture** and enter `https://mcp.aventure.vc/mcp` as the server URL.
3. Choose **OAuth** and automatic registration if prompted. Leave the client ID and secret blank.
4. Review the warning, select **I understand and want to continue**, then select **Create as a plugin**. Install the plugin and sign in to aVenture when prompted.
5. In a new chat, type `@` and select the installed **aVenture** plugin. Then [try a lookup](#check-the-connection).

[ChatGPT's custom server instructions](https://developers.openai.com/api/docs/guides/custom-mcp-server) cover workspace settings and plugin installation.

### Grok

On Grok Business or Enterprise, ask a team admin to [add aVenture to your team's connectors](https://docs.x.ai/grok/connector-management). Once they add it, open [Grok Connectors](https://grok.com/connectors), choose **aVenture**, and continue at step 3.

1. Open [Grok Connectors](https://grok.com/connectors). Choose **New Connector → Custom**.
2. Enter `https://mcp.aventure.vc/mcp` and name the connector **aVenture** if asked.
3. Sign in to aVenture and approve the connection. Return to Grok, open a chat, and [try a lookup](#check-the-connection).

[Grok's connector instructions](https://docs.x.ai/grok/connectors) explain personal and team setup.

### Perplexity

If you use Perplexity through an organization, an admin must turn on **Allow members to add custom connectors** before you can add your own.

1. Open [Plugins](https://www.perplexity.ai/computer/plugins) and choose **Add custom → Add MCP connector → Remote**.
2. Name it **aVenture** and enter `https://mcp.aventure.vc/mcp` as the **MCP server URL**.
3. Under **Advanced**, set **Authentication** to **OAuth** and **Transport** to **Streamable HTTP**. Leave the client ID and secret blank.
4. Check the acknowledgement box and select **Add**.
5. Open the **aVenture** connector card to sign in and enable it. Return to Perplexity and [try a lookup](#check-the-connection).

[Perplexity's remote connector instructions](https://www.perplexity.ai/help-center/en/articles/13915507-adding-custom-remote-connectors) also cover organization-wide setup.

### Gemini

Google requires a personal Google Account, age 18 or older, US access, English, and Gemini **History** turned on. Add the connector on the web; you can use it on web or mobile afterward.

1. Open [Gemini](https://gemini.google.com). Go to **Settings → Connected Apps**, then **Custom apps**. In some versions, **Connected Apps** is under **Personal Intelligence**.
2. Paste `https://mcp.aventure.vc/mcp` into the **Add a custom app** field, or select **Add a custom app** first if you already have one. Select **Next**.
3. Sign in to aVenture and approve the connection. Return to Gemini.
4. In a chat, type `@`, select **aVenture**, and [try a lookup](#check-the-connection).

[Google's custom app instructions](https://support.google.com/gemini/answer/17209137?hl=en) list the current account requirements.

### Claude Code

If you already connected aVenture in Claude on the web, check `/mcp` in Claude Code first. When you sign in to Claude Code with your Claude subscription, web connectors can appear there without another setup.

1. Run this in your terminal. `--scope user` makes aVenture available across your projects on this machine. Omit it to add the server only for the current project.

   ```bash
   claude mcp add --scope user --transport http aventure https://mcp.aventure.vc/mcp
   ```

2. Open an interactive Claude Code session. Enter `/mcp`, select `aventure`, and choose **Authenticate**. Sign in to aVenture and approve the connection in your browser.
3. Return to Claude Code. Confirm `/mcp` shows `aventure` as connected, then [try a lookup](#check-the-connection).

If `aventure` is already configured, run `claude mcp get aventure` in your terminal and check its URL before adding another entry. Current Claude Code versions also support `claude mcp login aventure` from the terminal. [Claude Code's MCP instructions](https://code.claude.com/docs/en/mcp#authenticate-with-remote-mcp-servers) cover command-line sign-in over SSH.

### Cursor

Add this entry to your [Cursor MCP configuration](https://cursor.com/docs/context/mcp#using-mcpjson). If the file already has an `mcpServers` object, add `aventure` inside it without replacing your other servers.

```json
{
  "mcpServers": {
    "aventure": { "url": "https://mcp.aventure.vc/mcp" }
  }
}
```

In **Customize**, open the server and sign in to aVenture when prompted. In chat, check that aVenture's tools appear under **Available Tools**, then [try a lookup](#check-the-connection).

### Gemini CLI

Google moved unpaid and Google One users from Gemini CLI to [Antigravity CLI](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli). Use these steps if you still use Gemini CLI.

1. Run this in your terminal to add aVenture across your projects on this machine:

   ```bash
   gemini mcp add --scope user --transport http aventure https://mcp.aventure.vc/mcp
   ```

2. Open Gemini CLI, enter `/mcp auth aventure`, and complete the aVenture sign-in in a browser on the same machine.
3. Return to Gemini CLI. Confirm `/mcp list` shows `aventure` as connected, then [try a lookup](#check-the-connection).

If your remote machine can't open a browser and receive the sign-in redirect, run Gemini CLI on your local machine instead. [Gemini CLI's MCP instructions](https://geminicli.com/docs/tools/mcp-server/) explain how it signs in and lists connected servers.

### Researchly

aVenture is already built into Researchly. Open [Profile → MCP servers](https://researchly.chat/profile/mcp-servers), choose **Connect aVenture**, and sign in. Then [try a lookup](#check-the-connection).

### Another MCP Client

Add a remote server named **aVenture** and paste this server URL:

```text wordWrap
https://mcp.aventure.vc/mcp
```

- **Transport:** Streamable HTTP
- **Authentication:** OAuth (sign in to aVenture in your browser)

If asked how to register the OAuth client, choose automatic registration. You don't need to create an API key or enter a client secret for browser sign-in. Then [try a lookup](#check-the-connection).

## Check the Connection

After you connect aVenture and enable it for your chat, paste this:

```text wordWrap
Read the aVenture record for
stripe.com. Use aventure_read,
operation getEntityLookup,
with query.urlDomain stripe.com.
Give me the company name and
the publicUrl from that result.
If either is missing, say so.
Don't use the web or memory.
```

The check passes when aVenture returns the Stripe record and the answer includes the profile link from that result. A help message, a failed tool call, or a link from a web search doesn't count. This check reads an existing profile; it doesn't start a research run.

## Troubleshooting

- **aVenture is connected, but the answer uses the web.** Enable or select aVenture in this chat, then retry. If the app asks to use an aVenture tool, allow the lookup.
- **The connector only answers questions about these docs.** If the server URL ends in `/_mcp/server`, it searches documentation, not company data. Replace it with the server URL in [your app's setup steps](#choose-your-ai-app).
- **The server URL shows `405` in your browser.** Paste it into your app's connector settings instead. It isn't a web page.
- **Sign-in finished, but the app still shows aVenture as disconnected.** Return to the connector settings and choose **Connect** or **Authenticate** again. If it still fails, send [support](/support) your app name, the step that failed, and the exact error. Leave out tokens, keys, and sign-in links.
- **A connection that worked before now returns `401`.** Sign in again from your app's connector settings. `/mcp` opens those settings in Claude Code.
- **A tool returns `402` (`subscription_required`).** The app reached aVenture. Try the website lookup above, or check [which plan includes the feature](/plans-and-usage).
- **A tool returns `429`.** Check the error for which limit you reached and when to retry. [Plans and usage](/plans-and-usage#when-you-reach-a-limit) explains allowances.

<Accordion title="Run the Server Yourself">

If you need to run the server inside your own network, use Node.js 24.22.1 or a newer 24.x release:

```bash
npm install --global @aventurevc/mcp-server
aventure-mcp-server
```

Leave it running and set `http://localhost:3333/mcp` as the URL in your local MCP client. Use Streamable HTTP and send an [aVenture API key](/authentication#create-an-api-key) as the bearer token on each request:

```json
{
  "mcpServers": {
    "aventure": {
      "type": "http",
      "url": "http://localhost:3333/mcp",
      "headers": {
        "Authorization": "Bearer <your-api-key>"
      }
    }
  }
}
```

Keep the key in your client's secret storage, not in version control. If you change `AVENTURE_MCP_PORT` or `AVENTURE_MCP_PATH`, update the URL in your client too. The package is on [npm](https://www.npmjs.com/package/@aventurevc/mcp-server) and its source is on [GitHub](https://github.com/aventurevc/aventure-mcp).

</Accordion>
